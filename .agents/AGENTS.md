# Project Rules

## Database Migrations

- Never delete or rewrite committed Alembic migration history.
  If a schema change is required or a previous migration is incorrect, create a new migration that applies the corrective change.
  Only rewrite migration history if the user explicitly requests a full database reset or migration history rebuild.

- Migrations should be compatible with the supported database backends for this project.
  When backend-specific behavior is unavoidable, implement it explicitly in the migration rather than replacing or deleting previous migrations.

- Before committing a migration:
  - Review the autogenerated migration.
  - Test `alembic upgrade head`.
  - Ensure an existing database can be upgraded without manual intervention.
